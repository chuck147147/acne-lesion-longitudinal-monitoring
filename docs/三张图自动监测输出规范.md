# 三视角痤疮模型监测

## 使用方法

双击项目根目录的 `start_acne_monitor.pyw`，选择本次左侧视角、右侧视角、下巴视角三张照片。界面默认复用最近一次已完成人工复核的结果作为基准，也可从同一个结果目录选择 `current_01_annotated.jpg` 至 `current_03_annotated.jpg` 更换基准。基准直接读取已复核框和等级，不重跑痘痘检测或分级模型。人工复核窗口只包含本次三张照片，基准照片及其标注仅作旁边的参考图。首次使用可清除基准，建立首个会话。每次复核结束都会更新全部历史时点的趋势图；“查看长期趋势”可只汇总既有结果，不运行检测或分类模型。要设置本机默认基线，可复制 `monitor.local.example.json` 为 `monitor.local.json`，填写 `baseline_run` 结果目录；未配置时自动使用最新已复核结果。本机配置不会提交到仓库。

命令行等价方式：

```powershell
.\.venv\Scripts\python.exe scripts\monitor_three_photos.py `
  --current <本次左侧图> <本次右侧图> <本次下巴图> `
  --baseline-run <上次已复核结果目录>
```

旧式 `--previous <左侧原图> <右侧原图> <下巴原图>` 参数仍可用于命令行兼容场景，但会重新检测上次照片；常规随访应使用 `--baseline-run`。

单独从已保存结果重建历史趋势：

```powershell
.\.venv\Scripts\python.exe scripts\monitor_three_photos.py --history-only
```

输出写入 `outputs/acne_monitor_runs/<时间戳>/`。每次使用独立目录，不覆盖旧结果。每次结果目录同时包含 `longitudinal.png` 和 `longitudinal.csv`；最新汇总也保存在 `outputs/acne_monitor_history/`。

历史时点从三张照片的源路径提取日期/时段。同一组三张照片按图像内容去重，不同的照片组会保留为不同记录，因此同一天分批拍摄的照片不会被合并；没有可读日期的已复核照片按结果生成时间显示。若存在 `*_longitudinal_tracking*_review*/face_alignment_summary.csv` 人工复核摘要，程序也会自动读取它作为历史活动框计数；同一天有多个会话时分别保留为批次。早期记录会注明纳入照片数，不会为缺失视角填零；区域负担分图只显示具有完整三视角复核统计的时点。未复核/状态未知点用空心点显示。逐颗追踪使用面部配准和一对一相似度筛选自动延续 `track_id`，并累积在本地追踪表。自动配对可能误配；未配对病灶保留独立编号，不自动判为新发或消退。

## 模型和逐病灶状态

- 候选框来自现有 ACNE04 单类 YOLO 检测器；逐框类别来自现有 0*–IV 分类器。`0*` 是痘印/瘢痕候选，排除在活动性皮损计数之外。
- 逐框结果包含检测置信度、分类置信度、区域、位置和模型类别。模型置信度是模型分数，不是临床概率。
- 左右侧脸配准使用相机侧眼部锚点和该侧下颌线轮廓，过滤画面外的预测点，并用稳健拟合剔除不一致锚点；下巴继续使用双眼、鼻、口中心和下巴锚点。配准通过后，再以局部颜色/纹理描述相似度为主要线索，并结合脸部相对位置、框大小和类别自动建立一对一对应。竞争相近或代价偏高的框会保留未对应状态。
- `rank_score` 和 `appearance_similarity` 都是图像特征排序参考，不是病灶身份概率；自动对应可能错配。
- 未配对框分别保留独立 `track_id`，记录为本次未建立连续关系；它们不被自动称为消退或新发。配准失败时，不自动延续该视角的病灶编号。
- 丘疹 II 和脓疱 III 同属浅表炎症级别，原型分权重相同。II 与 III 的转换会记录类别变化，不会单因标签数字变化而算成负担升降。

检测框面积达到图像面积的 0.45% 时，程序会截取框附近区域并以约 3 倍尺度再次运行同一个检测器。复检若出现多个更小候选，就用小框替换大框；若仍不能可靠拆分，则保留原框并在复核列表显示“**大框需拆分**”。此处是检测框细化，不是像素级分割。`lesions.csv` 和复核标注表中的 `detection_source` 会记录是否由大框细化或待人工拆分。

## 区域统计和整脸数值

三张输入分别对应三个固定视角/区域：左侧视角、右侧视角、下巴视角。每个区域都先汇总 I、II、III、IV、0* 数量，再给出活动性总数、炎症性总数、结节数、负担分及与基线的差值。

透明的项目原型分为：

```text
负担分 = I × 1 + II × 2 + III × 2 + IV × 4
```

此分数是工程原型，并非经临床验证的痤疮量表。结果同时输出每一类的原始计数；不会只用一个总分代替皮损分布。区域、三视角活动框、炎症框、结节框、负担分的前后值和差值写入 `region_summary.csv` 与 `report.md`。基线分为 0 时，相对变化率写 `N/A`，只给绝对差值。

`Δ` 对计数和负担分均按“本次 − 上次”计算：负值表示本次数值更低，正值表示本次数值更高。负担变化率按“(上次 − 本次) ÷ 上次 × 100%”计算；正值表示负担分下降，负值表示负担分上升；上次负担分为 0 时显示 `N/A`。

`report.md` 的数值结论包括各区域逐项变化、三视角检测框计数变化、炎症性框变化、结节变化、负担分差值/变化率、几何配对候选数及候选权重下降/不变/上升数。报告直接呈现这些数值，不把多维变化缩成二元结论。

## 输出文件

- `current_01_annotated.jpg` 至 `current_03_annotated.jpg`：本次照片的圈划与逐框类别。
- `previous_01_annotated.jpg` 至 `previous_03_annotated.jpg`：基准照片的已复核圈划与逐框类别。
- `comparison_01.jpg` 至 `comparison_03.jpg`：同视角上次/本次并排图；相同 `L` 编号表示自动匹配后延续的对应病灶。
- `overview.png`：左脸、右脸和已摆正方向的下巴三行合成图，每区展示前后照片、分级计数、变化值，底部汇总三视角。
- `longitudinal.png`、`longitudinal.csv`：每个已记录时点的区域负担分趋势图和区域分类/活动框统计表。
- `lesions.csv`：逐病灶模型结果、稳定编号及时间状态。
- `candidate_tracks.csv`：跨会话自动对应、编号延续状态、颜色/纹理相似度、匹配代价和配准距离。
- `track_observations.csv`、`track_summary.csv`：本次逐颗观察及所有稳定编号的历史摘要。
- `region_summary.csv`：分区原始计数、负担分和前后变化。
- `result.json`：机器可读汇总，包含分数定义、框复核状态和自动追踪摘要。
- `outputs/acne_monitor_history/lesion_tracks.csv`：仅保存在本机的逐颗长期观察表，一行对应一个病灶在一个时点的观察。
- `report.md`：区域结论、整组数值结论和图像链接。

## 解读边界

输入照片应按相同三个视角顺序拍摄。三张图可能重复拍到同一病灶，所以三视角合计称作“检测框合计”，不等于去重后的全脸唯一病灶数。本工具只在相同视角的相邻时点之间自动追踪，不进行跨视角去重。

分类器产生的是项目逐框标签，不是临床整脸分级。加权分只用于本项目内部查看同一受试者的时间变化；在完成专家标注校准、重复拍摄误差分析和外部验证前，不用它替代医生评估。
