# 后续随访照片流程

## 输入照片

每次提供同一人的三张照片，顺序固定为左侧视角、右侧视角、下巴视角。尽量保持拍摄距离、光线和角度一致；保留原图，并记录能核实的日期和会话信息。未知日期留空，不根据外观猜测。

## 运行模型

双击项目根目录的 `start_acne_monitor.pyw`，选择本次三张原图。程序默认使用最近一次已完成人工复核的结果作基线，也可从同一结果目录选择三张 `current_XX_annotated.jpg` 切换基准。本机默认基线可在 `monitor.local.json` 中设置 `baseline_run`，该文件不会提交到仓库。基准的已修正框和等级直接读取保存结果，不重新运行痘痘检测或分级。

每次运行在新的 `outputs/acne_monitor_runs/<时间戳>/` 目录生成圈划图、同视角对比图、逐病灶 CSV、分区统计、全时点 `longitudinal.png`/`longitudinal.csv` 和 `report.md`。趋势汇总和逐颗追踪记录保存在 `outputs/acne_monitor_history/`。人工修正窗口只包含本次三张照片；如有上次基准，配准通过且通过一对一相似度筛选的候选会自动延续稳定编号。自动错配可能把编号接错；没匹配上的病灶保留独立编号，不自动判定新发或消退。还可在程序里点“查看长期趋势”，只更新趋势文件，不运行检测或分类模型。完整字段和公式见 [`三张图自动监测输出规范.md`](三张图自动监测输出规范.md)。

系统按三张原图的内容识别同一时点，避免重复运行时重复计入；同一天不同照片组保留为独立批次。已有人工确认摘要会自动作为早期活动框记录导入，缺少的拍摄视角会显示实际照片覆盖数，不按零填补。长期图把早期人工标注活动框与近期复核结果放在活动框时间线上，完整三视角的区域负担分另行展示。逐颗追踪根据相邻时点的自动配对延续 `track_id`，并在本地 `lesion_tracks.csv` 中累计观察。自动匹配可能误配；未匹配或本次未检出的病灶不会自动判为消退。

## 复核规则

- 先看每个视角的逐病灶类别和数量，再看炎症性病灶、结节、原型负担分及其前后差值。
- 如果复核列表标记“大框需拆分”，检查这块是否包含多颗痘：删掉过大的框，再逐颗补框；程序会对大框先做局部放大复检，能自动找到小框时会直接替换。
- 左右侧脸用相机侧眼部点和下颌线轮廓配准；配准仍未通过时，该区只比较计数，不自动延续病灶编号。
- 配准通过后，系统按相似度和一对一匹配结果自动延续 `track_id`。候选排序分不是病灶同一性的概率；光线、姿势和取景变化可能造成错配。未配对框不能直接解释为新发或消退。
- 分类置信度和检测置信度是模型分数。发现漏检、误检或错误类别时，应先修正标注，再把修订纳入后续训练或评价数据。
- 三个视角可能重复看到同一病灶。三视角计数合计是检测框合计，不作为去重后的全脸唯一病灶数。

## 结果解释

I–IV 是项目逐框类别，不是临床整脸分级。负担分是未完成临床验证的工程原型；照片条件变化和模型错误都可能影响计数。输出用于同一人的图像记录和算法研究，不替代临床评估。
